# 未確認対話のAI事前修正

画像と対話の**全ターン**をCodex CLIの `gpt-6-luna` で点検する。OCR・カウントの注釈対象ターン以外も修正対象。ChatGPTのCLI認証を使い、OpenAI APIキーやローカルGPUは使用しない。

## 対象と保存

- 2026-11-17の初回スナップショット: **24,666件**。
- 対象: 承認必須・未承認・画像と対話あり・画像の整合性確認済み。
- 同じコレクション・UIDに人間の操作履歴があるデータは除外する。承認・編集・却下・未確認への戻しも含む。
- 開始前と修正案保存前に、現在の人手操作、元テキストのフィンガープリント、画像の実ハッシュを再確認する。変わっていればスキップ。
- 原本JSONLと人手承認履歴は書き換えない。修正案は `data/curation/ai_dialogue_suggestions.sqlite3` に別保存する。
- 元テキスト・画像が同一の修正案は上書きしない。各リクエストのプロンプト・応答・実行ログ・ハッシュを保存する。

## 人による確認

Webのアノテーション画面で、修正済みの対話に「AI事前修正（未承認）」が付く。元の対話、変更理由、注釈の差分も確認できる。

上部の「AI事前確認」で「AI事前確認済み・人手未確認」を選ぶと、処理済みの対象だけを一覧にできる。「AIの注意点あり・人手未確認」は判断が残るデータだけに絞る。処理中も一覧が更新されるが、開いている対話や編集中の下書きは置き換えない。

承認時には、**画面に表示された修正後の内容**を既存の編集・承認処理へ保存する。必要ならさらに手動で編集できる。承認後は既存の音声生成の対象となり、古い音声やアライメントがあれば再生成待ちとなる。

AIの処理完了は人手承認ではない。承認必須のデータは、人が承認するまで音声生成・学習へ進めない。既に開いている画面や編集中の文章を、後から到着したAI案で置き換えない。

`needs_attention` の結果には、曖昧な文字・数などの確認理由を表示する。不確かな補助注釈は自動で正解にせず、元の値を残して重点確認を促す。AIによる修正の正確性は保証できないため、画像との照合は引き続き必要。

## 英字を含むOCRと発話の読み方

2026-11-17に、英字を含む看板等の修正ルールを明確化した。正解注釈 `recognized_text` は画像上の原表記（大小文字・数字・記号を含む）を保持し、対話本文は音声として自然な読みへ修正する。たとえば注釈は `Gong cha 貢茶` のまま、発話は「ゴンチャという店名が、英字と漢字で書かれています。」とする。

読み取りと意味の説明は区別し、単なる小文字化や翻訳だけでOCR回答を済ませない。未知の店名の読みは創作せず、明瞭な短い綴りなら文字名で伝え、正式な読みが不明なことを注意点に残す。全ターンで名称・読み方をそろえる。

ワーカーはリクエストごとにプロンプトを読み込むため、変更後に開始する処理から適用する。実行中だったリクエストと処理済みの修正案は上書きしない。各リクエストの保存済みプロンプトで適用した規則を確認できる。

この分離はAI修正→人手承認の経路に適用する。新規対話生成側には原表記を回答に含むことを求める別の検証があるため、そちらへ流用する際は検証規則も併せて見直す。

## 実行と再開

プロジェクトルートで実行する。

ChatGPTでログイン済みのCodex CLIを用意し、`gpt-6-luna` と画像入力が利用できることを確認する。ワーカーは `exec --ignore-user-config --ephemeral --output-schema` などのオプションを使うため、それらに対応するCLIが必要。API認証への自動切り替えは行わない。

CLIは既定で `PATH` 上の `codex` を探す。IDE拡張に同梱された実行ファイル等を使う場合は、`run --codex /path/to/codex` で明示する。実行ファイルが見つからない場合は、処理を開始せず修正方法を表示する。

```bash
# 初回のみ。既存のキューは上書きしない。
.venv-data/bin/python ssvd/curate_pending_dialogues.py snapshot

# 進捗
.venv-data/bin/python ssvd/curate_pending_dialogues.py status

# 未完了から再開。排他ロックで二重起動を防止する。
.venv-data/bin/python ssvd/curate_pending_dialogues.py run --workers 2

# 問題解決後に失敗分を再試行対象へ戻す（自動では行わない）。
.venv-data/bin/python ssvd/curate_pending_dialogues.py retry-errors
```

今回の常駐実行は `start_new_session=True`、標準入力は `/dev/null` で起動しているため、SSH切断による終了を避ける。サーバー再起動後は上記 `run` で再開する。

- PID: `logs/ai_curation_luna_20261117.pid`
- ログ: `logs/ai_curation_luna_20261117.log`
- キュー: `data/curation/codex_luna_pending_20261117/queue.sqlite3`
- 各件の証跡: 同ディレクトリの `artifacts/<入力の識別ハッシュ>/attempt_<N>/`。`identity.json` でUID・コレクション・元データのハッシュを照合できる。初期20件のみ旧配置 `artifacts/<UID>/attempt_<N>/` に保存。
- 共通プロンプト: `ssvd/curation_prompt_ja.md`

`SIGTERM` / `SIGINT` は次のデータの取得を停止し、実行中のリクエスト終了を待つ。中断時に `running` のままだったデータは再開時に戻す。一般的な失敗は最大3回、利用上限・認証・モデル指定の異常は処理を停止し、別モデルやAPIへの自動切り替えは行わない。

最初の5件の試行後、質問への回答のつながりと不要な英単語混入の検査を強化した。最初の5件も元の修正案・プロンプトをそのまま保存しており、後続との違いは各件のプロンプトとハッシュで追跡できる。
